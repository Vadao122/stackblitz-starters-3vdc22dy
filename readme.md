Базовые принципы наименования н поинта:
1. Исользовать сущ во множественном числе.
Правильно /users Не правильно /getUser
2. Использовать вложенность для связей ресурсов
Пример: /users/{userId}/orders - получение пользовательских заказов
3. Использовать kebab-сase для сложных названий
Пример: /item/{itemId}/upload
4. Избегать лишних слов (не добавлять галоголы, если это не требуется)
Пример: /products а не /getProducts


Как выбрать http метод:
1. Создать -> POST -> Создаем новый ресурс.
Используется когда у ресурса нет id.(за исключением иерархической вложенности)
2. Получить -> GET -> Возвращает данные не изменяя ресурсы, а также содеражит query параметры
Пример: GET /users?id=2
        GET /users?filters={status:"active"}
        Все что после ? содержит имя и полседующий знак = является query параметром
        Если query параметр содержит {} значит он явялется JSON форматом
3. Обновить(Изменить) -> cut(полная замена) или patch(частичное обновление) -> обновляет существущий ресурс
Пример: PUT /users/{userId}/avatar
        PATCH /users/{userId}/settings
4. Удалить -> DELETE -> Удаляет или помечает, как удаленный ресурс по id
Пример: DELETE /items/{itemId}


Когда использовать query параметры:
1. Необходимо фильтровать, сортировать или искать по данным
2. Передача необязательнх параметров
Например: ключ сортировки ?sortKey = 1 ?sort = "ASC" ?sort = "DESC"
          GET /products?name=DESC - будет сортировка по имени
          GET /products?sort={name="DESC"; price="ASC";}
          GET /products?page=1&limit=50 page-это страница, limit-кол элементов на стр
3. Передача данных, которая не является частью индификатора ресурса
Пример: GET /search?q=Android


Когда использовать PATH параметры:
PATH параметры - это часть url в фигурных скобках. Пример: POST /items/{itemId}/upload
1. Необходимо указать обязательных индификатор ресурса, Например в методах POST CUT PATCH или DELETE
2. Реализация иерархической связи ресурсов
Пример: POST /users/{usersId}/photo


Когда использовать body(тело запроса):
1. В случае передачи данных, которые требуют шифрования
2. При передачи большого кол данных. Например: массив или объект
3. В методах POST CUT и PATCH
body представляет из себя JSON объект привиденный к строковому представлению
